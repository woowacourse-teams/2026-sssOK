# 개발 Nginx 컨테이너 전환 사전 검증

기존 호스트 Nginx를 유지하면서 별도 Docker Nginx로 API·로그·중앙 수집 경로를 검증했다.
개발 기본 Compose와 CD에는 정식 Nginx를 추가한 상태이며 서버 포트 인계와 실제 CD 실행은 아직 확인 전이다.
SSE 실제 연결 검증은 사용자 요청으로 생략했다. 운영은 기존 구성을 유지한다.

- `default.conf.template`: API와 호스트·앱 지표 프록시 후보. 환경 라벨과 중앙 IP만 지정 변수로 치환한다.
- `compose.preview.yml`: 독립 프로젝트에서 Nginx 하나만 실행한다. 기존 앱 네트워크는 외부 네트워크로 참조한다.
- 실제 개발 앱 네트워크 이름을 확인해 `DEV_DOCKER_NETWORK`로 지정해야 한다.
- API 임시 포트는 loopback 18080, 중앙 수집 임시 포트는 개발 사설 IP 19101이다. 먼저 미사용 여부를 확인한다.
- 호스트의 기존 80·19100과 앱·node_exporter 포트는 이 단계에서 그대로 유지한다.
- 새 컨테이너는 `sssok-nginx-preview` 서비스 라벨을 가진다. 기존 Alloy가 Docker 로그를 수집하는지 확인한다.
- access log는 쿼리 문자열을 제외한 JSON이며, error log의 민감값 처리는 기존 Alloy 마스킹을 유지한다.

## 서버 전환 전 확인

문법 검증만으로 실제 요청 전달이나 로그 수집이 검증되지는 않는다.

- 기존 API와 임시 API의 health·응답 헤더를 비교한다.
- 인증된 SSE의 연결 유지와 이벤트 전달을 확인한다. 토큰을 로그나 문서에 기록하지 않는다.
- 중앙에서 임시 포트의 `/metrics`와 `/app-metrics`를 조회하고, 비허용 출발지와 헤더 위조 요청은 차단되는지 확인한다.
- 임시 Nginx의 JSON 로그가 기존 개발 Loki에서 조회되고 환경·요청 ID·민감값 처리가 올바른지 확인한다.
- 검증 후 기본 개발 Compose·CD·검사 스크립트를 함께 전환한다. 현재 CD의 호스트 Nginx 파일 비교도 전환 시 변경해야 한다.
- 포트 인계 시 호스트 Nginx를 중지하고 Docker가 80·19100을 사용한다. 실패하면 새 Nginx를 중지하고 호스트 Nginx로 복귀한다.
- 다음 배포에서 관측 유지까지 확인한 뒤 8081·9100의 임시 loopback 게시를 제거한다. 8080 직접 접근 사용 여부도 먼저 확인한다.
- 호스트 로그 파일과 기존 Loki·Prometheus·Grafana 볼륨은 삭제하지 않는다.

## 운영 적용 전 별도 검토

이 후보를 운영에 그대로 덮어쓰지 않는다. 개발 검증 후 공통 설정과 운영 전용 설정의 경계를 확정한다.

- 운영 ALB의 신뢰 대역·원래 스킴·클라이언트 IP 처리.
- 기존 운영 Grafana의 host 라우팅과 WebSocket.
- 공통 SSE 처리와 개발·운영 CI/CD 동시 검증.
- 기존 운영 과거 지표·로그 유지.

## 로컬 검증 결과

- Compose 구문 검사 통과.
- Nginx 공식 이미지에서 환경변수 치환 후 `nginx -t` 통과.
- 실제 개발 네트워크·API·SSE·로그·중앙 접근 시험은 서버에서 진행해야 한다.

## 서버에서 확인한 결과와 현재 전환 상태

- 기존 호스트 Nginx는 enabled이며 활성 설정은 sssok-dev.conf와 sssok-log-format.conf이다.
- 앱과 node_exporter는 app_sssok 네트워크를 사용한다.
- 임시 API health 200, 요청 ID 한 줄과 JSON 로그의 ID 일치를 확인했다.
- 중앙에서 임시 19101의 호스트·앱 지표를 조회했다.
- 개발 자체 요청과 중앙 IP를 넣은 X-Forwarded-For 요청은 두 경로 모두 403이었다.
- 기존 개발 Loki에서 preview 서비스 로그를 요청 ID로 찾았다. 중앙 로그 이전 완료를 뜻하지 않는다.
- SSE 검증은 미실시이며 실제 외부 클라이언트 IP 보존도 아직 확인하지 않았다.
- 정식 개발 Compose는 동일 템플릿을 사용하고 80·사설 19100을 게시한다. 로그 서비스 라벨은 sssok-nginx이다.
- 개발 CD의 호스트 파일 비교를 제거하고 호스트 서비스 active/enabled 차단으로 바꿨다.
- 템플릿 변경은 개발 Nginx 재생성으로 반영하므로 배포 때 짧은 접속 중단이 발생할 수 있다.
- 앱·수집기의 기존 호스트 게시 포트와 Alloy의 호스트 로그 마운트는 복귀·과거 로그 보존을 위해 유지했다.
- 초기 전환 시 호스트 설정을 백업하고 Nginx 자동 시작을 비활성화한 뒤 정식 컨테이너를 실행한다.
- 전환 실패 시 Docker Nginx를 중지하고 호스트 Nginx를 다시 활성화한다. 데이터 볼륨은 삭제하지 않는다.
