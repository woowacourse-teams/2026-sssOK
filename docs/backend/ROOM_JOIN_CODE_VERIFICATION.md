# 방 코드 없는 입장 거부 확인 (#626)

#604 dev 검증(T31·T32)에서 roomId만 알면 초대 링크 없이 남의 방에 입장해 사진을 볼 수 있다는 문제가 발견됐다.
입장 API가 방 코드를 받아 확인하도록 고친 뒤, 실제 서버에 요청을 보내 다음 두 가지를 확인했다.

- 초대 링크(방 코드)가 없는 사람은 방에 들어올 수 없고, 방의 어떤 자원에도 접근할 수 없다
- 초대 링크를 받은 사람은 지금처럼 들어와 이용할 수 있다

바뀐 입장 계약은 [ROOM_MEMBERSHIP_API.md](ROOM_MEMBERSHIP_API.md#입장)에 있다.

## 등장 계정

- H: 방장. 방, 폴더, 사진 한 장을 갖고 있다
- S: 초대 링크를 받지 않은 사람. H의 roomId는 알지만 방 코드는 모른다. 자기 방이 하나 있어 그 방의 코드는 안다
- I: 초대 링크를 받은 사람. H의 방 코드를 안다

## 확인하면서 알게 된 점 (이번 범위 밖)

- 방 단위 API의 참여자 확인(`RoomMembershipInterceptor`)은 방 존재·만료를 참여 여부보다 먼저 검사한다. 그래서 참여자가 아닌 사람도 roomId를 바꿔 가며 응답(404·410·403)으로 방이 있는지, 만료됐는지 알 수 있다. 사진 같은 자원은 열리지 않는다.
- 실시간 구독(SSE)은 첫 하트비트(15초 주기)를 보낼 때 응답 헤더가 나간다. 연결 직후에는 상태 코드를 받을 수 없다.

## 남은 확인

- dev 서버에서 #604의 T31·T32 요청을 다시 보내 확인하는 일은 머지 후 dev에 자동 배포되면 이 스크립트를 `BASE=https://dev-api.ssssok.com/api/v1`로 실행해 결과를 덧붙인다. dev는 사진을 실제 업로드로 넣어야 하므로 `PSQL` 없이 실행하면 C07~C09는 건너뛴다.
