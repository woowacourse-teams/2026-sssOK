**현재 결과는 JNI 배포 전 dev 서버 기준선이다.** JNI/FFM 로컬 비교와 실제 서비스 지연을 구분한다. JNI 배포 후 실서버 수치는 아직 없다.

## 배포 후 및 인스턴스 분리 순서

1. JNI 코드를 기존 dev 사양에 배포한 뒤 같은 원본·장수·동시성·워커·AI·추적 설정으로 20/100/200장을 반복한다.
2. 위 표의 JNI 배포 후 칸을 실제 k6/Tempo 결과로 채운다. JNI 내부 decode/resize/encode는 현재 미계측이므로 0ms로 표시하지 않는다.
3. 이미지 전용 워커 인스턴스를 분리하고 같은 행렬을 반복해 API 지연·큐 대기·CPU·메모리를 확인한다. API 쪽 워커를 끄는 명시적 역할 설정이 먼저 필요하다.
4. 이미지 처리 부하가 빠진 API의 메모리·GC·응답 지연을 확인한 뒤 API 사양을 한 단계 낮추고 다시 측정한다.
5. prod는 배포 전 자체 기준선을 확보한 뒤 배포 후 동일 조건으로 비교한다. dev와 prod 간 차이를 개선율로 계산하지 않는다.
