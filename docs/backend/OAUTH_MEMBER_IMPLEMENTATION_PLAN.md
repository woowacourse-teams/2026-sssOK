# OAuth 회원 기능 구현 계획 (#595)

## 목적과 합의한 범위

익명 사용자와 회원 모두 방을 생성하고 참여할 수 있다. 카카오·애플 가입 또는 로그인을 통해 현재 익명 사용자의 활동을 계정에 연결하고, 후속 작업인 내 방 목록 조회의 기반을 마련한다.

- 신규 소셜 계정에 가입할 때 유효한 익명 인증이 있으면 기존 회원 ID와 활동을 유지한다.
- 기존 소셜 계정에 로그인할 때 현재 익명 사용자의 참여 기록·방장 권한·업로드 소유권을 통합한다.
- 카카오·애플은 별도 계정으로 취급하고 이메일만으로 자동 연결하지 않는다.
- 로그아웃은 요청에 사용한 세션만 무효화한다.
- 탈퇴 시 모든 인증과 연결 코드를 무효화하고 본인이 만든 방을 논리 삭제한다.
- 다른 사람의 방에 올린 파일은 유지하고 작성자는 ‘탈퇴한 사용자’로 표시한다.
- 재가입 시 이전 활동과 권한은 복구하지 않는다.

| 내 방 목록 API·약관 동의 | 후속 작업 | 이번 인증 작업 범위에서 제외 |

회원 상태 메서드가 있다는 사실과 실제 가입·통합·탈퇴 기능이 완료됐다는 것은 구분한다. 현재 추가한 외부 API는 로그아웃, 카카오·애플 로그인 시작·완료, 회원 탈퇴다. 기존 계정에 익명 활동을 통합하는 요청도 지원하며 제공자는 기본 비활성화다.

## 현재 인증 구조

- `renewal/incoming/auth`: 기존 인증 API, 회원 인증 인자 처리, 로그아웃 API.
- `renewal/application/auth`: 익명 인증·연결 코드 로그인과 세션 검증·무효화.
- `renewal/domain/member`, `renewal/domain/auth`: 회원·상태·닉네임과 연결 코드.
- `renewal/outgoing/database/member`, `renewal/outgoing/database/auth`: 저장 모델과 저장소.
- `renewal/outgoing/security`: JWT 서명·검증 및 서비스 인증 계약.
- `renewal/outgoing/oauth`: 카카오·애플 코드 교환, 사용자 확인, HTTP 호출과 애플 서명 키 관리.

`SessionTokenProvider`가 회원의 활성 상태와 세션 유효성을 확인한다. `JwtTokenProvider`는 JWT 자체의 서명·만료·주체를 검증하며, 그것만으로 서비스 접근을 허용하지 않는다.

### 세션 및 구형 토큰

새 로그인마다 독립된 세션 ID를 JWT에 넣고 `auth_session`에 저장한다. 현재 세션 로그아웃은 해당 기록을 무효화하며 다른 로그인 세션은 유지한다. V42에서 서비스 refresh token을 추가했다. Access 30분·refresh 30일 고정 만료이며 익명·연결 코드·소셜 로그인에 공통 적용한다. 갱신해도 세션 ID와 절대 만료 시각을 유지한다.

기존 토큰은 세션 ID가 없어 호환 처리가 필요하다. 개별 로그아웃은 원문 대신 토큰의 SHA-256 해시로 차단 기록을 저장한다. 전체 무효화는 `legacy_auth_revocation`에 회원별 차단 기록을 남겨 한 번도 사용하지 않은 구형 토큰도 거부한다. 같은 구형 토큰을 여러 기기에서 복사해 사용했다면 동일 인증으로 취급한다.

통합·탈퇴 상태는 구형·신형 인증 모두 거부한다. 전체 무효화 내부 기능은 세션과 연결 코드도 함께 정리한다. 회원 물리 삭제 시 두 인증 테이블의 기록은 DB의 `ON DELETE CASCADE`로 삭제된다.

### 로그아웃 API

- `POST /api/v1/auth/logout`
- 요청: `Authorization: Bearer {accessToken}`
- 성공: `204 No Content`
- 인증 누락·잘못된 토큰·만료·이미 무효화된 인증: `401`
- 쿼리 파라미터 토큰은 받지 않는다.

인증 차단은 이후 요청 검증에 적용된다. 이미 연결된 SSE의 종료 정책은 별도 점검 대상으로 남아 있다.

## 현재 결정과 다음 순서

프론트 코드는 수정하지 않는다. 쿠키·HttpSession 대신 단일 서버의 Caffeine 메모리 캐시에 로그인 진행 정보만 저장한다. 자세한 API 목표와 제한은 [연동 문서](OAUTH_PROVIDER_INTEGRATION.md)를 따른다.

| 순서 | 작업 | 상태 / 완료 기준 |
| --- | --- | --- |
| 1 | 쿠키 없는 API 계약 | state·loginVerifier·code로 시작과 완료를 연결 |
| 2 | 로그인 시도 저장소 전환 | 메모리 캐시 구현 완료. 5분 만료·최대 10,000건 정책·조건부 원자적 소비 |
| 3 | 카카오 시작 API | 구현 완료. 선택적 익명 인증, 고정 인가 URL, state·loginVerifier·만료, no-store 응답 |
| 4 | 카카오 가입·로그인 및 활동 통합 | 완료. 참여·방장·업로더·좋아요·다운로드·의견 통합, 중복 정리 및 익명 인증 폐기 |
| 5 | 애플 연결 | 구현 완료. 웹 code/query 시작·완료 API와 nonce 검증 연결. 공통 가입·로그인·통합 처리 재사용 |
| 6 | 탈퇴 및 공개 전 검증 | 전체 인증 무효화·본인 방 삭제·작성자 표시·제공자 연결 해제·실제 연동 |

서비스 → 저장소와 도메인 모델은 유지한다. DB를 쓰지 않는 로그인 시도에는 JPA 계층을 두지 않는다. 회원·소셜 계정·서비스 인증 세션 구조를 재사용한다. OAuth 진행 확인용 loginVerifier를 유지한다. 서비스 refresh 기능에는 V42 해시 기록, 웹 refresh 쿠키와 credentials CORS를 추가했다.

로그인 시도용 V39는 적용 이력을 훼손하지 않도록 보존하고 V40으로 테이블만 제거한다. 서버 재시작 또는 캐시 한도에 따른 제거 시 진행 중 로그인은 다시 시작한다. 여러 서버로 늘어나면 공유 저장소를 재검토한다.

익명 사용자가 없을 때 신규 닉네임은 `사용자`로 둔다. 기존 회원·익명 회원은 닉네임을 유지한다. 통합 시 회원 ID 오름차순으로 잠근다. 중복 참여는 더 이른 입장 시각을 유지하고 좋아요는 한 건으로 합친다. 자세한 규칙은 연동 문서를 따른다. 제공자 토큰 암호화 저장은 구현했다. 탈퇴 흐름은 연결했고 실제 제공자 인증·연결 해제 검증 전에는 공개하지 않는다.

## 후속 범위

내 방 목록 API, 여러 소셜 로그인 수단 연결, 약관 동의·이력·관리 화면은 별도 작업이다. 현재는 가입 대기 회원이나 가입용 임시 인증값을 선제적으로 만들지 않는다.

카카오 완료 API 단계: `CompleteKakaoLoginService`는 로그인 시도 소비와 제공자 호출을 조정하고, `SocialMemberLoginService`는 회원 잠금·가입·소셜 연결·인증 교체를 하나의 DB 트랜잭션으로 처리한다. 신규 익명 가입은 ID와 닉네임을 유지한다. 이 단계 당시에는 기존 계정 + 익명 활동을 503으로 차단했으며, 이후 활동 통합 단계에서 지원하도록 변경했다.

카카오 완료 API 추가 후 전체 기본 테스트: 1,722개 중 1,704개 통과, 18개 건너뜀, 실패 0개. 신규 가입·재로그인·익명 인증 교체·동시 가입 롤백·상태 재검증·완료 요청 검증을 포함한다. 실제 카카오 계정 연동은 미검증이다.

익명 활동 통합 단계: SocialMemberLoginService가 MergeAnonymousMemberService를 호출한다. 통합 서비스가 참여·좋아요 중복 정리, 소유권 이전, 의견 작성자 연결, 회원 상태와 인증 변경을 조정한다.
