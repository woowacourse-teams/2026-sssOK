# OAuth 회원 기능 구현 계획 (#595)

## 목적과 합의한 범위

익명 사용자와 회원 모두 방을 생성하고 참여할 수 있다. 카카오·애플 가입 또는 로그인을 통해 현재 익명 사용자의 활동을 계정에 연결하고, 후속 작업인 내 방 목록 조회의 기반을 마련한다.

- 신규 소셜 계정에 가입할 때 유효한 익명 인증이 있으면 기존 회원 ID와 활동을 유지한다.
- 기존 소셜 계정에 로그인할 때 현재 익명 사용자의 참여 기록·방장 권한·업로드 소유권을 통합한다.
- 카카오·애플은 별도 계정으로 취급하고 이메일만으로 자동 연결하지 않는다.
- 로그아웃은 요청에 사용한 세션만 무효화한다.
- 탈퇴 시 모든 인증과 연결 코드를 무효화하고 본인이 만든 방을 논리 삭제한다.
- 다른 사람의 방에 올린 파일은 유지하고 작성자는 ‘탈퇴한 사용자’로 표시한다.
- 재가입 시 이전 활동과 권한은 복구하지 않는다.

## 구현 현황

| 단계 | 상태 | 결과 |
| --- | --- | --- |
| 회원·인증 renewal 이전 | 완료 | 모델·서비스·컨트롤러·저장소·회원 토큰 및 테스트 이전, 기존 API 경로 유지 |
| 회원 상태 기반 | 완료 | ANONYMOUS / REGISTERED / MERGED / WITHDRAWN 상태와 허용 전환, 저장·복원, V36 마이그레이션 |
| 세션·로그아웃 | 완료 | 세션별 JWT 식별자, 서버 검증, 현재 세션 로그아웃, 전체 인증 무효화 내부 기능, V37 마이그레이션 |
| 소셜 계정 모델·제공자 인증 | 미구현 | 다음 구현 단계 |
| 소셜 회원가입·로그인·활동 통합 | 미구현 | 데이터 이전과 가입 API 구현 필요 |
| 탈퇴 API·방 삭제·작성자 표시 | 미구현 | 현재 상태 모델·인증 차단 기반만 준비됨 |
| 내 방 목록 API·약관 동의 | 후속 작업 | 이번 인증 작업 범위에서 제외 |

회원 상태 메서드가 있다는 사실과 실제 가입·통합·탈퇴 기능이 완료됐다는 것은 구분한다. 현재 외부 API로 새로 추가한 기능은 로그아웃이다.

## 현재 인증 구조

- `renewal/incoming/auth`: 기존 인증 API, 회원 인증 인자 처리, 로그아웃 API.
- `renewal/application/auth`: 익명 인증·연결 코드 로그인과 세션 검증·무효화.
- `renewal/domain/member`, `renewal/domain/auth`: 회원·상태·닉네임과 연결 코드.
- `renewal/outgoing/database/member`, `renewal/outgoing/database/auth`: 저장 모델과 저장소.
- `renewal/outgoing/security`: JWT 서명·검증 및 서비스 인증 계약.

`SessionTokenProvider`가 회원의 활성 상태와 세션 유효성을 확인한다. `JwtTokenProvider`는 JWT 자체의 서명·만료·주체를 검증하며, 그것만으로 서비스 접근을 허용하지 않는다.

### 세션 및 구형 토큰

새 로그인마다 독립된 세션 ID를 JWT에 넣고 `auth_session`에 저장한다. 현재 세션 로그아웃은 해당 기록을 무효화하며 다른 로그인 세션은 유지한다. 토큰 갱신 기능은 아직 추가하지 않았다.

기존 토큰은 세션 ID가 없어 호환 처리가 필요하다. 개별 로그아웃은 원문 대신 토큰의 SHA-256 해시로 차단 기록을 저장한다. 전체 무효화는 `legacy_auth_revocation`에 회원별 차단 기록을 남겨 한 번도 사용하지 않은 구형 토큰도 거부한다. 같은 구형 토큰을 여러 기기에서 복사해 사용했다면 동일 인증으로 취급한다.

통합·탈퇴 상태는 구형·신형 인증 모두 거부한다. 전체 무효화 내부 기능은 세션과 연결 코드도 함께 정리한다. 회원 물리 삭제 시 두 인증 테이블의 기록은 DB의 `ON DELETE CASCADE`로 삭제된다.

### 로그아웃 API

- `POST /api/v1/auth/logout`
- 요청: `Authorization: Bearer {accessToken}`
- 성공: `204 No Content`
- 인증 누락·잘못된 토큰·만료·이미 무효화된 인증: `401`
- 쿼리 파라미터 토큰은 받지 않는다.

인증 차단은 이후 요청 검증에 적용된다. 이미 연결된 SSE의 종료 정책은 별도 점검 대상으로 남아 있다.

## 남은 작업 순서

### 1. 소셜 인증 계약과 계정 모델

- 공식 문서 기준 카카오·애플의 입력 값, 서버 검증, 리다이렉트·클라이언트 식별 조건을 확정한다.
- `(provider, providerUserId)` 유일성을 보장하는 소셜 계정 모델과 JPA·DB 제약을 추가한다.
- 신규 가입 시 익명 사용자가 없을 때의 닉네임 결정 방식과 오류 응답을 정한다.
- 외부 인증 요청 타임아웃·실패 처리·검증 테스트를 구현한다.

### 2. 가입·로그인과 익명 활동 통합

- 신규 가입과 기존 계정 로그인을 별도 처리하고, 가입 완료 전 약관 검증을 추가할 경계를 둔다.
- 통합할 익명 사용자는 현재 인증에서만 식별한다.
- 참여·방장·업로더 데이터 외에 좋아요·의견 등 회원 참조 데이터의 처리 기준을 확정한다.
- 중복 참여 시각, 중복 좋아요 등 충돌 처리 규칙을 정한다.
- 회원 잠금 순서를 통일하고 가입·통합 재시도 및 동시 요청의 원자성을 검증한다.
- 통합 상태 저장·소유권 이전·기존 인증 무효화를 하나의 일관된 처리로 연결한다.

### 3. 탈퇴

- 탈퇴 상태와 전체 인증 무효화, 본인 방 삭제를 연결한다.
- 다른 사람의 방에 남긴 파일의 작성자 표시를 변경한다.
- 소셜 연결 해제·개인정보 정리·재가입 정책을 구체화한다.
- 실제 파일 보관 및 영구 삭제 정책을 확정한다.

### 4. 공개 전 통합 검증

- 전체 인증·방·업로드 회귀 및 실제 제공자 연동을 검증한다.
- 기존 토큰 호환 종료 시점과 만료 세션 정리 정책을 정한다.
- 요청당 DB 인증 조회의 부하와 장시간 SSE의 무효화 처리를 확인한다.
- API 문서와 클라이언트 연동 계약을 확정한다.
- 약관·개인정보 안내 및 필요한 동의 항목을 별도 확인한다.

## 후속 범위

내 방 목록 API, 여러 소셜 로그인 수단 연결, 약관 동의·이력·관리 화면은 별도 작업이다. 현재는 가입 대기 회원이나 가입용 임시 인증값을 선제적으로 만들지 않는다.

## 이번 정리의 검증 결과 (2026-10-25)

최종 상태에서 전체 기본 테스트 1,628개 중 1,610개가 통과했고 18개는 기존 조건에 따라 건너뛰었다. 실패는 없었다. 성능·실제 외부 서비스 테스트는 기본 실행 범위에 포함되지 않는다. 이전만 적용한 중간 상태와 회원 상태까지 적용한 중간 상태도 각각 관련 테스트로 검증한다.
