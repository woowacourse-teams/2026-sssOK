# 제품 요구사항 정의서 - 쏙(sssOK)

링크 하나로 여는 단발성 이미지·영상 공유 공간
앱 설치, 번호 교환, 계정 생성 없이 모여서 사진을 나눠 가진 뒤 각자의 목적을 이루고 파한다.

- 랜딩 페이지 : https://2026-sss-ok-landing.vercel.app/
- 프로토타입: https://sssok-prototype.vercel.app/

## 왜 만드는가

카톡으로 사진 300장을 받아도, 그중 내가 나온 것만 골라내는 건 여전히 사람이 손으로 해야 하는 일이다. 개수 제한 때문에 나눠 보내다 실패하고 어디까지 보냈는지 헷갈리며, 누가 어떤 사진을 찍었는지 몰라 재요청도 못 하고, 한 장을 보려고 전체를 내려받는다. 단체 사진 공유는 보내는 쪽과 받는 쪽 양쪽 모두에게 불편하다.

**모아서 콘텐츠를 만드는 쪽에서는 더 크게 깨진다.** 20~30명이 각자 찍은 촬영본을 한곳에 모으는 단계에서 쓰던 도구가 전부 실패한다. 밴드는 업로드할 때 화질이 깨져서 **아예 쓰지 않게 됐다.** 카톡은 대용량을 보내는 중에 **앱을 벗어나면 전송이 멈춰** 창을 붙잡고 기다려야 하고, 그러고도 자주 실패한다. 그렇게 받은 사진·영상은 화질이 깨져 편집 소재로 쓸 수 없다.

인터뷰로 확인한 불편의 근거, 경쟁 채널(카톡·슬랙·드라이브)과 비교한 지향점은 [RESEARCH.md — 1장 문제 정의](./RESEARCH.md#1-문제-정의)에 정리했다.

## 누구를 위한 것인가

첫 유저는 "찍는 사람"이 아니라 "모으는 사람"이다. 여러 명이 찍은 촬영본을 한 명(또는 소수)이 모아서 콘텐츠로 만드는 팀 — 1차 진입점은 대학 홍보대사 · 학생회 홍보부 같은, 카톡을 트기엔 아직 공적인 사이인 그룹이다.

왜 이 타겟인지, 어떤 대상은 의도적으로 제외했는지는 [RESEARCH.md — 4장 타겟층 정의](./RESEARCH.md#4-타겟층-정의-3주차-한정)에 정리했다.

## 이 서비스만의 핵심 가치

- **원본 그대로** — 카톡·밴드처럼 압축하지 않는다. 편집 소재로 쓸 수 있는 유일한 공유 채널. **첫 한 마디로 내세우는 것은 이것 하나다.**
- **설치·가입 없음** — 링크 하나로 익명 게스트로 바로 참여
- **한 공간에 모인다는 구조적 이점** — 채널·스레드·DM으로 흩어지지 않으니, 나중엔 "옮기는 것"을 넘어 "정리해서 건네주는 것"까지 할 수 있는 유일한 위치에 있다
- **모임이 끝나면 사라진다** — 정해진 시간이 지나면 방과 데이터가 자동으로 없어진다. 이건 부가 기능이 아니라 위의 "원본 그대로"를 가능하게 하는 전제다. 쌓아두지 않으니까 압축하지 않을 수 있다([features/001-room.md](./features/001-room.md) 참고)

"원본 그대로"를 맨 앞에 두고 나머지는 들어온 다음에 보여주는 이유는 [RESEARCH.md — 3장](./RESEARCH.md#3-차별화-전략)에 정리했다.

## 무엇을 만드는가

기능은 영역별로, 화면은 화면별로 별도 문서에 나눠 담았다. 각 문서의 절마다 붙은 상태 표시로 지금 뭐가 있고 뭐가 없는지 바로 확인할 수 있다.

### 상태 표시의 뜻

기준은 **실제 코드**다. 프로토타입에서 동작하는 것과는 별개로 본다.

| 상태          | 뜻                                                              |
| ------------- | --------------------------------------------------------------- |
| **구현됨**    | 만들어져서 지금 동작한다                                        |
| **미구현**    | 무엇을 만들지는 정해졌고, 아직 안 만들었다 — **바로 착수 가능** |
| **미정**      | 무엇을 만들지부터 아직 안 정해졌다 — **논의가 먼저 필요**       |
| **문제 있음** | 만들어져 있지만 의도대로 동작하지 않는다                        |

**미구현**과 **미정**의 구분이 핵심이다. 미구현은 이 문서만 보고 개발을 시작할 수 있다는 뜻이고, 미정은 만들기 전에 먼저 이야기를 나눠야 한다는 뜻이다.
