# PR 규칙

## PR 생성 조건

- 하나의 PR은 하나의 관심사만 다룬다 (기능 하나, 버그 하나 단위로 쪼개기)
- 이슈와 반드시 연결 (`Closes #12` 형식으로 본문에 명시 → 머지 시 이슈 자동 종료)
- PR 제목은 [커밋 컨벤션](./COMMIT_CONVENTION.md)과 동일한 접두사 사용: `feat: 결제 원장 등록 API 구현`
- 작업 영역(FE/BE) 체크박스로 표시 (모노레포이므로 리뷰어가 영역 파악 쉽게)

## PR 템플릿

```markdown
## 작업 내용
-

## 관련 이슈
Closes #

## 변경 사항
- [ ]
- [ ]

## 테스트
- [ ] 단위 테스트 작성/통과
- [ ] 로컬 동작 확인

## 리뷰 요청 사항 (선택)
-
```

## PR 크기 제한

- 변경량 기준 **500줄 이내** 권장 (diff 기준, 팀 합의로 조정 가능)
- 초과 시 기능/커밋 단위로 쪼개서 분리

## 리뷰 규칙

### 1차: CodeRabbit (자동 리뷰봇)

- PR 생성 시 자동으로 코드 스타일, 잠재 버그, 개선 제안 코멘트
- 참고용 1차 필터로만 활용

### 2차: 사람 리뷰

- 페어 approve 필요
- 본인 PR 셀프 머지 금지
- 리뷰 코멘트는 머지 전 모두 resolve
- 리뷰 코멘트 남기는걸 원칙으로 하되, 대면으로 이야기 할 수 있는 부분은 대면으로 진행
- CODEOWNERS 기반으로 `/frontend`, `/backend` 변경 시 해당 영역 팀원이 기본 리뷰어로 자동 지정

## 머지 조건

- CI(빌드+테스트) 통과 필수 (영역별 `paths` 필터로 변경된 부분만 실행)
- 브랜치가 최신 `main` 기준으로 업데이트된 상태여야 함
- 위 리뷰 조건(CodeRabbit + 사람 승인) 모두 충족
