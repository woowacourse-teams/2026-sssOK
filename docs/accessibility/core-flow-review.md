# 주요 기능 접근성 점검

범위: 이름 입력 → 갤러리 입장 → 사진 업로드 → 사진 조회.
화면의 문구·배치는 유지하고 각 요소에 접근성 정보를 연결한다.
실제 낭독과 코드·자동 테스트로 확인한 내용을 구분한다.

## 1. 이름 입력

| 질문 | 해결 방법 | 결과 문구 및 확인 상태 |
| --- | --- | --- |
| 입력란에 이름 레이블이 연결되어 있는가? | 입력란의 접근 가능한 이름을 지정하고 기존 시각적 레이블은 유지 | “표시할 이름”. 사용자 제공 개선 후 낭독 화면에서 확인 |
| 필수 입력·최대 12자 조건을 알 수 있는가? | required 속성으로 필수 상태 전달, 입력란 설명에 최대 길이·공개 범위 연결 | “최대 12자까지 입력할 수 있어요. 입력한 이름은 다른 사람에게 보여요.” 및 스크린리더의 “필수 사항”. 사용자 낭독 화면에서 확인 |
| 글자 수 표시의 의미를 알 수 있는가? | 화면의 0/12는 유지하고 접근성 트리에서는 풀어 쓴 문구 제공 | “최대 12자 중 0자 입력”. 입력값에 따라 갱신. 사용자 낭독 화면에서 확인 |
| 입장 버튼이 비활성화된 이유와 입력 오류가 전달되는가? | 버튼의 접근 가능한 이름에 미입력·공백만 입력한 이유 연결. 공백만 있는 입력은 aria-invalid로 전달 | 빈 값: “입장하기. 이름을 입력해야 입장할 수 있어요.” 사용자 낭독 화면에서 확인. 공백: “입장하기. 공백을 제외한 이름을 입력해야 입장할 수 있어요.” 입력란 오류: “공백을 제외한 이름을 입력해주세요.” 공백 사례는 실제 낭독 미확인 |
| 키보드로 입력하고 입장할 수 있는가? | 기존 form·submit 버튼·자동 포커스 유지, 유효한 입력 후 Tab으로 버튼 이동 | 자동 테스트에서 Tab 이동 확인. 기존 제출 테스트 통과. 실제 키보드 Enter 시나리오는 추가 확인 필요 |

활성 버튼의 현재 접근 가능한 이름은 “입장하기”. 처리 중에는 “입장하기. 입장 요청을 처리하고 있어요.”
스크린리더 자체의 삽입 위치·텍스트 편집·필수 사항·비활성화됨 등의 표현은 앱 문구와 구분한다.

| --- | --- | --- |
| 입장 성공과 현재 갤러리 이름을 알 수 있는가? | 기존 갤러리 제목의 접근 가능한 이름에 갤러리 종류·도착 사실 포함 (설명 속성만으로는 사용자 제공 화면에서 낭독이 확인되지 않아 보강) | “[갤러리 이름] 갤러리에 입장했어요.” 실제 낭독 확인 대기 |

## 4. 사진 조회

사용자 의견: 실제 이용 시 사진 조회 흐름은 대체로 정상 동작. 요청에 따라 코드만 검토하고 동작 코드는 수정하지 않음.

| 질문 | 코드 확인 결과·현재 구현 | 결과 문구 / 판정 |
| --- | --- | --- |
| 파일명 대신 사진 내용을 이해할 수 있는 설명이 제공되는가? | GalleryMediaCard의 썸네일과 MediaViewerModal의 확대 이미지 모두 alt에 fileName 사용. 카드 열기 버튼도 파일명 기반. Media 모델에 사진 내용 설명 필드 없음 | “[파일명] 크게 보기”, 이미지 대체 텍스트는 “[파일명]”. 내용 설명 제공은 미충족. 파일명·선택 상태 개선과 내용 대체 텍스트 제공은 구분해 기록 |
| 업로더와 목록 내 위치를 알 수 있는가? | 목록에는 업로더 배지(본인은 “나”), 확대 보기 하단에는 업로더 이름 표시. 다만 목록 카드 버튼의 aria-label이 파일명·동작으로 고정되어 버튼 이름에는 업로더가 포함되지 않음. 목록은 div 기반이며 개별 카드에 순번 정보 없음. 확대 보기 상단은 현재 순서 / 전체 개수를 aria-live=polite로 제공 | 업로더는 화면 텍스트로 제공하나 목록 버튼 탐색 시 전달은 추가 확인 필요. 확대 보기 위치는 “1 / 5” 형식. 목록 내 위치 안내는 미구현. 부분 충족 |
| 키보드로 사진을 열고 이전·다음 사진으로 이동할 수 있는가? | 사진 열기는 기본 button의 onClick. 확대 보기는 이전·다음 button 및 ArrowLeft / ArrowRight 처리. 첫·마지막 사진에서는 해당 이동 버튼 disabled. 삭제 확인 중에는 사진 이동 차단 | “이전 사진”, “다음 사진”. 구현 확인. 사용자 정상 이용 의견과 별개로 실제 키보드·스크린리더 조합별 결과는 별도 확인 |
| 크게 보기를 닫으면 원래 사진으로 돌아오는가? | dialog를 열기 전 document.activeElement 저장. 닫을 때 기존 요소에 focus 복원. Escape와 “갤러리로 돌아가기” 버튼으로 닫기 가능 | 열기 전 포커스 요소로 복귀하는 구현 확인. 사진 열기 버튼에서 열었다면 해당 버튼으로 복귀. 원래 사진이 삭제되어 DOM에서 사라진 경우 대체 포커스 지정은 없음 |

정리: 키보드 탐색과 닫기 후 포커스 복귀는 구현되어 있음. 사진 내용 설명과 목록 카드의 업로더·순번 전달까지 모두 완료된 것으로 기록하지 않음. 이번 단계에서는 개선 코드 추가 없이 현황만 기록.

### 갤러리 화면 추가 확인

- 사용자 제공 낭독 화면: 제목은 “테코톡 방”만 읽혔고 도착 설명은 표시되지 않았다. 접근 가능한 이름을 “테코톡 방 갤러리에 입장했어요.”로 변경. 변경 후 실제 낭독 확인 대기.
- 전체 버튼: “전체 0” 대신 “전체 사진 및 동영상, N개”와 aria-pressed로 선택 상태 전달. 화면 숫자와 접근성 문구는 동일한 totalCount 사용. 캡처의 5와 0 불일치 원인은 미확정.
- 개별 폴더: “[폴더 이름] 폴더, 사진 및 동영상 N개”와 선택 상태 제공.
- “사진 올리기, 버튼”은 목적을 전달하므로 유지. 진행·결과 안내는 업로드 단계에서 확인.
- “image 72.png 크게 보기”는 사진 조회 단계 개선 대상으로 기록. 내용 설명 데이터 유무 확인 후 대체 텍스트와 업로더·위치 안내를 구분해 처리 예정.

### 사진 선택 토글

- 질문: 사진 선택 여부를 알 수 있는가?
- 해결: aria-pressed는 유지하고 선택 토글의 접근 가능한 이름에도 상태를 명시. 시각적 UI는 유지.
- 미선택: “[파일명] 선택, 선택 안 됨”. 선택 후: “[파일명] 선택, 선택됨”.
- 사용자 캡처에서 기존 “토글 버튼”만으로 미선택 상태가 명확하지 않아 보강. 변경 후 실제 낭독 확인 대기.

### 사용자 재확인 결과 — 갤러리 입장

- 사용자 제공 개선 후 화면에서 “머리말 단계 1, 테코톡 방 갤러리에 입장했어요.” 낭독 확인.
- 사진 선택 토글에서 “[파일명] 선택, 선택 안 됨, 토글 버튼” 낭독 확인.
- 전체 버튼에서 “전체 사진 및 동영상, 0개, 선택됨, 토글 버튼” 낭독 확인. 화면에는 5개로 보이므로 개수 일치는 아직 확인되지 않음.
- 입장 직후 제목 타겟 요청: RoomSummary가 처음 나타날 때와 roomCode 변경 시 제목에 focus({ preventScroll: true })를 호출하도록 이미 구현되어 있음. 제목은 tabIndex=-1로 프로그래밍 방식 포커스가 가능하며 일반 Tab 순서에는 추가하지 않음.
- 자동 테스트에서 입장 후 제목이 document.activeElement인지 확인. 실제 VoiceOver 커서가 입장 직후 제목을 따라가는지는 별도 사용자 확인 필요 (요소를 수동 탐색해 읽은 캡처만으로 자동 이동까지 확인할 수 없음).

## 3-1. 업로드 오류 모달 접근 불가 — 사용자 확인 및 개선

- 사용자 관찰: “올릴 수 없는 형식이에요” 모달이 열려도 자동으로 모달에 진입하지 않으며, 모달 내부로 이동하거나 확인 버튼을 실행하기 어려움. 기존에 대화상자 이름이 읽혔다는 사실만으로 조작 가능하다고 판단하지 않음.
- 원인(코드): 공통 Modal이 일반 div에 role=dialog와 aria-modal만 선언. 최초 포커스 이동·포커스 순환·배경 비활성화 동작 없음.
- 해결: 공통 모달을 네이티브 dialog.showModal()로 열어 최상위 모달 계층에 표시하고 배경을 비활성화. 열릴 때 대화상자 자체에 포커스를 옮김. Tab/Shift+Tab으로 내부 버튼 순환, Escape로 닫기, 닫은 뒤 이전 요소가 남아 있으면 포커스 복원. 콜백이 바뀌는 일반 재렌더링에는 초기 포커스를 반복하지 않음.
- 제목·설명: 업로드 거절/실패 모달의 제목과 본문을 aria-labelledby / aria-describedby로 명시적으로 연결. 시각적 문구·배치 유지.
- 기대 안내(거절 사례): “올릴 수 없는 형식이에요” + 대화상자 역할 + 기존 용량 제한·나머지 업로드 진행 설명. 내부 탐색 시 “[파일명] · [용량]”, “지원 안 함”, “확인, 버튼” 접근 가능.
- 질문: 실패 이유와 대응 방법이 전달되는가? 모달이 열렸을 때 내부로 이동하고 확인·재시도 버튼을 키보드로 실행할 수 있는가?
- 실제 VoiceOver 재검증 대기. 자동 테스트의 포커스 이동·버튼 실행 결과와 실제 스크린리더 조작 결과는 구분.
- 확인 제한: 열기 전 요소가 업로드 진행 중 제거되었다면 해당 요소로의 복귀는 불가. 실제 업로드 흐름에서 복귀 위치도 확인 필요.

### 오류 모달 사용자 재확인 및 문서화

- 개선 후 모달 내부 접근이 가능하다는 사용자 확인을 받음.
- 첨부 화면에서 “머리말 단계 2, 올릴 수 없는 형식이에요”, 용량 제한 안내, “확인, 버튼” 낭독 확인.
- 모달 자동 진입·확인 실행·닫은 뒤 복귀의 전체 실제 흐름까지 확인한 것으로 확대 해석하지 않음.
