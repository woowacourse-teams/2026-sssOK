# 배포 PR 생성

배포 전에 저장소 루트의 `AGENTS.md` 를 읽고 "배포" 섹션 규칙을 따른다.
(세부 배경이 필요하면 `docs/deployment/DEPLOYMENT.md` 도 함께 읽는다.)

**`deploy` 브랜치에 병합되는 순간 CD 파이프라인이 돌아 실제 서버에 배포된다.**
되돌리기 어려운 동작이므로 절차를 건너뛰지 않는다.

## 작업 절차

1. `main` 과 `deploy` 를 최신으로 받는다.
2. `deploy..main` 커밋 목록을 뽑아 **이번 배포에 무엇이 나가는지** 정리한다.
3. `main` 의 CI 가 통과 상태인지 확인한다. 실패했으면 배포하지 않고 알린다.
4. 배포에 영향을 주는 변경이 있는지 확인해 사용자에게 알린다.
   - DB 마이그레이션 (`backend/src/main/resources/db/migration/`)
   - 환경변수 추가·변경 (`.env.prod.example`)
   - 인프라·컴포즈 설정 (`docker-compose.prod.yml`, `Dockerfile`)
5. 나갈 변경 목록과 위 주의 항목을 보여주고 **PR을 만들지 확인받는다.**
6. 승인되면 `main → deploy` PR을 만들고 링크를 알려준다.

## 주의 사항

- **이 스킬은 PR을 병합하지 않는다.** 병합은 사람이 한다.
  사용자가 병합을 요청하더라도, 무엇이 배포되는지 다시 보여주고 한 번 더 확인받는다.
- 이미 리뷰된 코드가 올라가는 흐름이라 재리뷰는 하지 않는다.
- `deploy` 에 직접 커밋하거나 푸시하지 않는다. 반드시 PR 을 거친다.
- 새 환경변수가 필요한 배포라면, 서버 `.env` 에 값이 채워져 있는지 먼저 확인하도록 안내한다.
  CI 는 서버의 `.env` 를 덮어쓰지 않으므로 값이 없으면 기동에 실패한다.
- 배포 후 헬스체크가 실패하면 파이프라인이 직전 이미지로 롤백한다. 그 사실을 사용자에게 알린다.
