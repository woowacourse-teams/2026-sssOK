# 커밋

커밋하기 전에 저장소 루트의 `AGENTS.md` 를 읽고 "커밋" 섹션 규칙을 따른다.
(세부 배경이 필요하면 `docs/collaboration/COMMIT_CONVENTION.md` 도 함께 읽는다.)

## 작업 절차

1. 현재 브랜치를 확인한다. `main` 이나 `deploy` 면 **커밋하지 않고** 작업 브랜치를 만들도록 안내한다.
2. `git status` 와 `git diff` 로 무엇이 바뀌었는지 파악한다.
3. 변경을 **관심사 단위로 묶는다.** 하나의 커밋은 하나의 이유로 설명될 수 있어야 한다.
   묶음마다 프로덕션 코드와 그에 딸린 테스트를 함께 넣는다.
4. 각 묶음이 단독으로 컴파일되도록 순서를 정한다 (의존하는 쪽이 나중).
5. `AGENTS.md` 형식에 맞춰 메시지를 쓴다. 본문에는 무엇을 왜 바꿨는지를 적는다.
6. **커밋 메시지 전문과 대상 파일 목록을 사용자에게 보여주고 확인을 받는다.**
7. 승인되면 묶음별로 `git add` 후 커밋한다.

## 주의 사항

- **확인 없이 커밋하지 않는다.** 사용자가 아직 검토 중일 수 있다.
- 커밋 메시지에 에이전트 서명이나 `Co-Authored-By` 트레일러를 넣지 않는다. 공개 저장소다.
- 이슈가 아직 안 끝났으면 `Closes #` 를 커밋에 넣지 않는다. 이슈가 조기에 닫힌다.
- 관련 없는 변경(포맷팅, 임시 파일, 설정)이 섞여 있으면 커밋 전에 알린다.
- 비밀값(`.env`, 키, 토큰)이 스테이징에 포함됐는지 확인하고, 있으면 멈추고 알린다.
- 푸시는 이 스킬의 범위가 아니다. 푸시가 필요하면 별도로 확인을 받는다.
