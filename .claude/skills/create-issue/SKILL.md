# 이슈 생성

이슈를 만들기 전에 저장소 루트의 `AGENTS.md` 를 읽고 "작업 순서"와 "이슈" 섹션 규칙을 따른다.
(세부 배경이 필요하면 `docs/collaboration/ISSUE_GUIDE.md` 도 함께 읽는다.)

**작업은 이슈에서 시작한다.** 이미 코드를 고치기 시작했더라도, 브랜치를 만들기 전에 이슈부터 만든다.
이슈 번호가 브랜치·커밋·PR을 잇는 유일한 추적 키이기 때문이다.

## 작업 절차

1. 무엇을 하려는 작업인지 확인한다. 불명확하면 사용자에게 묻는다.
2. 작업 영역을 정한다 — 프론트엔드만인지, 백엔드만인지, 양쪽인지, 저장소 전반인지.
3. 영역에 맞는 제목 접두사와 라벨을 `AGENTS.md` "이슈" 섹션에서 고른다.
4. 작업 성격에 맞는 템플릿을 `.github/ISSUE_TEMPLATE/` 에서 고른다
   (`feature.md` / `bug.md` / `refactor.md` / `chore.md`).
5. 템플릿의 각 섹션을 채운다. **완료 조건은 검증 가능한 문장으로 쓴다** —
   "잘 동작한다" 대신 "만료된 방에 입장하면 홈으로 이동한다" 처럼.
6. 생성할 내용(제목·라벨·Assignee·본문)을 사용자에게 보여주고 **확인을 받는다.**
7. 승인되면 `gh issue create` 로 만들고, 생성된 이슈 번호를 알려준다.

## 주의 사항

- **확인 없이 이슈를 만들지 않는다.** 이슈는 팀 전체에 보이는 산출물이다.
- Assignee 가 정해지지 않았으면 누구로 할지 묻는다. 비워두지 않는다.
- 이미 같은 내용의 열린 이슈가 있는지 `gh issue list` 로 먼저 확인한다.
- 이 스킬은 브랜치를 만들지 않는다. 브랜치는 `create-branch` 스킬을 사용한다.
