# 브랜치 생성

브랜치를 만들기 전에 저장소 루트의 `AGENTS.md` 를 읽고 "브랜치" 섹션 규칙을 따른다.
(세부 배경이 필요하면 `docs/collaboration/BRANCH_STRATEGY.md` 도 함께 읽는다.)

## 작업 절차

1. 이 작업에 연결된 GitHub 이슈 번호를 확인한다.
   이슈가 없으면 먼저 만들도록 안내한다 (`create-issue` 스킬).
2. 이슈 제목과 라벨에서 타입과 영역을 정한다.
   판단이 애매하면 추측하지 말고 사용자에게 묻는다.
3. `AGENTS.md` 의 브랜치 형식에 맞춰 이름을 만든다. 설명은 3~5단어 이내 kebab-case.
4. 분기 기준 브랜치를 정한다 — `hotfix` 가 아니면 `main`, `hotfix` 면 `deploy`.
5. 분기 기준 브랜치를 최신으로 받는다 (`git fetch` 후 `git pull --ff-only`).
   작업 트리에 커밋하지 않은 변경이 있으면 먼저 사용자에게 알린다.
6. 브랜치를 만들고 체크아웃한다.
7. 만든 이름과 근거(이슈 번호·타입·영역)를 요약해 보여준다.

## 주의 사항

- 브랜치명이 규칙과 어긋나면(이슈 번호 누락, 대문자, 언더스코어 등) 만들기 전에 확인한다.
- 이미 같은 이슈의 브랜치가 원격에 있는지 확인한다. 있으면 새로 만들지 말고 그것을 쓰도록 안내한다.
- 이 스킬은 커밋하지 않는다. 커밋은 `commit-changes` 스킬을 사용한다.
- 브랜치 생성은 로컬 동작이라 되돌리기 쉽다. 다만 원격 푸시는 별개이며, 푸시는 사용자 확인을 받는다.
