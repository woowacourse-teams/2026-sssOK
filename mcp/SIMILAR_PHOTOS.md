# 연사·유사 구도 분류 (#661)

## 범위와 선택

`group_similar_photos`는 동일 인물 여부가 아니라 사진 전체의 유사 구도를 비교한다.
DINOv2 ViT-S/14 전체 이미지 cosine과 ORB 기하 매칭을 0.7:0.3으로 결합한다.
`score = .7 * dino_cosine + .3 * min(3 * orb_score, 1)`이다.
ORB는 500개 특징점, ratio .75, RANSAC 4px, 최소 매칭 8개를 사용한다.
검출 특징점 수 중 인라이어 비율을 ORB 점수로 사용하며 점수는 확률이 아니다.

기본 하한은 결합 점수 .54, ResNet50 중앙 이미지 cosine .72이다.
그룹 사이 모든 사진 쌍이 두 하한을 통과할 때만 병합한다. 서로 다른 양끝 사진이
중간 사진 하나로 연결되어 같은 그룹에 들어가는 현상을 제한한다.
입력은 mediaId로 정렬되며 동률은 이 순서를 따른다. 시간 정보는 현재 사용하지 않는다.

최소 표시 그룹은 3장이다. 2장 후보는 `smallGroupMediaIds`, 1장은 `unassignedMediaIds`로
분리하여 소규모 후보를 숨기더라도 결과에서 잃지 않는다. 그룹 간 사진 중복은 없다.
오류 사진까지 포함하면 모든 입력 사진이 정확히 한 범주에 속해야 결과를 커밋한다.
읽을 수 있는 사진이 하나라도 있으면 개별 준비 오류와 함께 결과를 반환한다.
전부 디코딩 실패하면 실행이 실패한다. 모델 추론 실패는 전체 실행 실패다.

## 개발 품질 검증과 한계

기존 개발 사진 62장으로 12가지 방법·조합을 비교했다. AI 임시 구도 정답과 그룹별
내부 교차검증에서 DINOv2+ORB를 우선 후보로 선택했다. 이는 독립 검증이 아니다.
사용자가 36~39번을 같은 묶음으로 확인하고 소규모 그룹을 줄이도록 요청해 위 기준을
추가 조정했다. 기준만 낮출 때 다른 인물의 비슷한 사무실 배경이 섞여 중앙 이미지
비교를 추가했다. 이 기준을 62장 전체에 적용한 결과는 18개 그룹·62장이다.

실제 구현과 고정 추론 파일로 다시 실행해 18그룹·62장·오류 0을 확인했다.
이 수치는 정확도·재현율이 아니다. 새 장소·다른 피사체·조명·가로 사진·크롭 사진의
독립 품질 검증이 남아 있다. 앞선 교차검증 수치를 이 튜닝 정책 성능으로 재사용하지 않는다.
ORB 480×640 고정 리사이즈는 검토한 실험을 재현하며 다른 종횡비의 품질은 미검증이다.
사진·시연 결과·모델은 공개 저장소에 포함하지 않는다.

## 메모리와 실행

모델 두 개는 순서대로 로드하며 배치는 1이다. 인물 분류 모델은 이 작업에서 로드하지
않는다. 작업 종류 둘 모두 같은 단일 워커 대기열을 사용하여 동시에 모델을 올리지 않는다.
작업마다 별도 프로세스가 종료되므로 Python allocator가 보유한 메모리도 작업 종료 시 해제된다.

로컬 ARM64 Docker, 2 CPU, 1400MiB, 스왑 없음에서 측정했다.

| 입력 | 실행 범위 | 시간 | 컨테이너 최대 메모리 |
|---|---|---:|---:|
| 개발 JPEG 62장 | 실제 분석 파이프라인 | 14.9초 | 916MiB |
| 100장 (기존 사진 반복) | 부모·워커·SQLite·정리 | 28.5초 | 1088MiB |

둘 다 OOM 0. 단일 실행이며 컨테이너 값은 cgroup `memory.peak`로 파일 캐시도 포함한다.
100장 시험은 개수 상한의 자원 검사이며 새로운 품질 자료가 아니다. 24MP 등 최대
해상도·크기 조합에 대한 메모리 보장은 아니다. EC2에서 동일 조건 검증은 아직 수행하지 않았다.

## 모델 준비

`model-checksums.json`은 기존 4개와 `dinov2.pt`, `resnet50.pt`를 모두 검증한다.
추가 두 파일의 실행 중 검증에는 `similar-model-checksums.json`을 사용한다.
준비한 모델 6개가 있어야 readiness가 성공하며 배포 사전 검사도 모두 확인한다.
파일 해시를 검증한 동일 열린 파일에서 모델을 로드한다. 런타임 다운로드는 없다.

추가 모델은 고정 입력 1×3×224×224 TorchScript 추론 파일이다. 원래 모델과 랜덤 입력의
출력을 atol/rtol 1e-4로 확인하고 개발 사진으로 결과도 확인했다. PyTorch에서 TorchScript가
deprecated이므로 향후 실행 환경 변경 시 export 방식과 수치·품질을 재검증해야 한다.
현재 파일은 고정 PyTorch 2.14.1·torchvision 0.29.1 환경에 맞춘 과도기 배포 형식이다.

재생성은 `scripts/export_similar_models.py --help`를 참고한다. 로컬 공식 소스와 체크포인트를
명시적으로 전달한다. 재생성 파일의 해시는 자동 승인하지 않는다. 결과 비교 후 두 manifest를
함께 갱신해야 한다. 준비 스크립트의 source 아래 `exported/`에 추가 두 파일을 배치한다.

- DINOv2 공식 코드·모델: https://github.com/facebookresearch/dinov2 (Apache-2.0)
- ResNet50 IMAGENET1K_V2: https://docs.pytorch.org/vision/stable/models/generated/torchvision.models.resnet50.html
- Torchvision 코드: https://github.com/pytorch/vision (BSD-3-Clause)

## 로컬 실행

```bash
cd mcp/servers/gallery
python -m pipeline.run_local --kind SIMILAR --input /path/to/photos \
  --output /path/to/new-result --assets-root /path/to/models --threads 2
# MCP 클라이언트에도 --kind SIMILAR 사용
```

LLM·Spring API·사용자 승인·삭제·폴더 반영은 후속 이슈다.

## 구현 검증 기록

- 새 ARM64 이미지에서 CI와 동일한 테스트 마운트·명령: 92개 통과.
- 배포 제어·복구 테스트 18개 통과. v1 업그레이드와 v2에서 v1 자동 롤백 차단 포함.
- HTTP MCP 도구 등록·접수, 종류별 멱등성, SQLite 이전, 결과 전체 분할 검사,
  오류 사진 ID 변환, 재시작 후 동일 결과 재전송, 연쇄 병합 차단을 확인했다.
- 62장 결과의 그룹별 사진 ID 구성이 사용자가 확인한 로컬 결과와 정확히 일치했다.
- GitHub CI, 실제 Spring/R2 연결, EC2 배포·복구는 수행하지 않았다.
